# 时间对比与首屏标签修复

2026-10-31。

## 核对结果

不同服务、排程解释、截图时间、倒计时阶段任一不同，都不应直接比较倒计时数字。竞品公开 HTML 当前仍显示 Global Asia 与旧静态快照；不能据此断言其动态选择器/当前计时一定与我们的服务设置相同。本轮无法通过网页抓取器读取本网站正式域名的 JSON，故不声称已经验证线上部署数据与本地完全一致。

按当前本地数据，在 2026-10-31 11:01 UTC：

- NA East 的下次开场是 12:00 UTC = 上海 20:00 = 纽约 08:00 EDT。
- Global Asia 的下次开场是 14:00 UTC = 上海 22:00 = 首尔/东京 23:00。
- 上海与阿姆斯特丹显示同一场次的本地小时不同，排程瞬时不应改变。

因此文档关于“服务选择不同导致不一致”的核心解释成立。但不能将“其他事件全部一致”或“Global 真实服务器时钟已经确认”作为结论，已有来源冲突仍在。

## 改动

- 原 `服务名 / 观众本地偏移` 标签移除。
- 显示时间单独标“Your time / UTC / Region display time”，附 IANA 时区和该场日期的偏移/缩写。
- 下一行明确同一场次的 `Schedule clock` 时刻、日期、规则时区与所选服务。用“排程时钟”而非声称已证实的“服务器时钟”，MetaBot 等方案也不会错误标为纽约时间。
- 主徽章用 Regional-clock / Unified UTC+9 / Fixed-UTC interpretation；内部 `confidence=disputed`、证据详情、来源页和日历中的分歧说明保留。
- 不采用“3 sources”计数：列出三个来源不表示三个来源都支持所选解释。
- 不修改排程数值、不自动切 Global Asia 来对齐竞品，也不声称做了 DST 游戏实测。

## 验证

单元/构建测试通过，浏览器回归增加上海、阿姆斯特丹两个显示时区的固定时刻检查，验证服务与观众时区不再混写，NA East / Global Asia 的排程时间分别正确。测试仍覆盖 11 月 1 日纽约 DST 的规则转换，实际游戏服务器是否采用此解释继续由来源状态说明。
